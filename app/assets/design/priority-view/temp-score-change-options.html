Option C · For the design team, not for participants

Three ways to show changes to the priority score

Today a changed score gets a tag and the old score ("Score decreased, from 4.4"). It does not say why it changed, or when, and it assumes everything is assessed at the same time. It is not.

The problem

The priority score is built from four inputs, and they are updated at different rates. A change to the score can come from any one of them, at any time. So a plain "since the last assessment" is vague, because each input has its own last assessment.

These rates are assumptions for this page, so please correct them.

Input How often it changes (assumed) Last update in these examples
Risk of incursionMonthly, and straight away if a case is confirmed in the UK6 October 2026, and 3 November for a confirmed case

Priority scoreRecalculated whenever any input changes3 November 2026

Because of this, a good design needs to answer three questions for someone looking at a changed score:

  • Why did it change? Which input moved?
  • When did it change? Is that recent, or a slow input updating?
  • Compared with what? Last month, last quarter, or the last time this input was assessed?

The mock-ups use the same fictional diseases as Option C, but the changes are only for this page. Bars and impact areas are left out so the changes stand out. All three follow the earlier decisions: text only with no arrows, outlined tags for change, and colour is never the only cue.

Option 1: say why, with the date

The change tag stays under the score. We add one plain sentence saying which input moved and when. Only the priority cell changes, and the other columns stay as they are.

How it handles different rates

Each sentence carries its own date and its own source ("October assessment", "quarterly review"). So a slow change and a fast change read the same way, and nobody has to know the schedule. If two inputs change, the sentence names both and gives both dates.

Good for

  • Answering "why did it change?" without leaving the page (T12)
  • The smallest change to Option C, and no new columns or controls

Watch for

  • The priority cell gets tall. Rows with several changes could get long
  • The sentence says what moved, but you have to look across to see the new value in context
  • Someone has to write the sentence, or it has to be generated from the data in a consistent form
  • It doesn't say which inputs are out of date, only which ones changed

Option 2: show each input's rhythm, and mark what moved

Each column heading says how often that input updates and when it last did. Cells whose input has changed show a small outlined mark ("Was High") and the date. The mark stays until that input is next updated, so slow inputs stay visible for longer without any extra rule. The priority cell keeps the existing tag.

How it handles different rates

The rate is shown once per column, in the heading, so people learn it and can spot an input that is overdue. A mark stays until its input is next updated. A monthly input's mark is replaced often, and a quarterly one stays for about three months. The reader sees which input moved, and how fresh each input is.

Good for

  • Showing which input moved, in the same place as its value
  • Making stale inputs obvious, which also helps trust (UN1)
  • Making it easy to scan down a column to see what changed this period

Watch for

  • Column headings get long, and the table is already wide
  • It shows what moved but doesn't link it to the priority change. People may have to work it out
  • An old mark from a slow input could look like a recent change, so the date matters
  • More marks on the page, and more to learn

Option 3: compare over a period you choose

People choose what to compare with: last month, last quarter or last 6 months. Every score, including priority, shows its change over that period. The comparison date is stated above the table, so there is no ambiguity about "since when".

How it handles different rates

The window does the work. "Last month" shows only fast changes: here, just Scaly claw fever, because the other two changed on 6 October and 30 September. "Last quarter" also catches the quarterly inputs. "Last 6 months" would catch a reassessment of impact. People pick the window that matches what they care about.

Good for

  • Being clear about "compared with what?", which the other two leave implied
  • Different roles, such as a monthly briefing and a quarterly review
  • Letting the team learn which window people really use

Watch for

  • A new control, and Option C already has a view switch and sorting
  • It needs a default, and the wrong one could hide a change. "Last month" would miss quarterly changes
  • It shows the net change over the window, not the individual steps within it
  • The "Was" marks carry no date or reason, so you still don't know why
  • The previous values for every window have to be available in the data

Suggestion

Start with option 1 in Option C. It answers the question people are most likely to ask, "why did it change?", in the cell they are already looking at. It is the smallest change, and because each sentence carries its own date, it copes with the different rates without anyone needing to learn the schedule.

Then add one thing from option 2: the "last updated" line in each column heading. It is cheap, and it shows which inputs are out of date, which helps with trust.

Keep option 3 for research. We don't yet know whether people want to choose a period. Ask what they compare with, and whether "since last month" is how they think. If they do, option 3 is the most honest way to deal with the different rates.

They are not exclusive. Options 1 and 2 combine easily, and option 3 could sit on top of either.

To confirm before we choose

  • The real rates. How often does each input change, and does a confirmed case really recalculate the score straight away?
  • When the score is recalculated. After every input change, or on a fixed date? This decides whether "from 4.2" can be one number.
  • How long a change stays visible. Until the next update, a fixed number of days, or until someone dismisses it?
  • Several changes at once. If risk and control measures both move, which one does the sentence lead with?
  • "No change" or "not assessed". Do we say so, now that some inputs are updated rarely? Showing nothing could mean either.
  • Who writes the reason, or whether it can be generated from the data.

If we test this, the closest task is T12 ("Himalayan Dragon Pox has dropped from 4.4 to 4.1. Where would you look to find out why?"). Add a follow-up: "How recent do you think that change is?"
